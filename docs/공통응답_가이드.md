# 공통 응답 및 예외 처리 가이드

## 개요

- MATJOM 백엔드는 모든 REST 응답을 `ApiResponse` 구조(`success`, `data`, `error`, `timestamp`)로 통일합니다.
- 컨트롤러는 DTO, 컬렉션, `void` 등을 그대로 반환하면 되고, `ResponseBodyAdvice`가 자동으로 포장합니다.
- 실패 응답은 `DomainException` 계층(예: `UserException`) 또는 기본 Spring 예외를 `GlobalExceptionHandler`가 받아 일관된 에러 포맷으로 내려줍니다.

## 주요 구성 요소

- `com.matjom.matjom.common.response.ApiResponse`
  - 성공: `ApiResponse.ok(data)` / `ApiResponse.ok()`
  - 실패: `ApiResponse.error(errorCode)` / `ApiResponse.error(errorCode, message)`
- `com.matjom.matjom.common.response.ApiResponseBodyAdvice`
  - 컨트롤러 반환값을 자동 감싸는 `ResponseBodyAdvice`
  - `ApiResponse`, `ResponseEntity`, `String`은 이미 포맷이 명시돼 있다고 보고 그대로 통과
- `com.matjom.matjom.common.exception.base.DomainException`
  - 모든 도메인 예외의 상위 클래스. 필수로 `ErrorCode`를 지정.
- `com.matjom.matjom.common.exception.base.*`
  - `AuthException`, `UserException` 등 도메인별 파생 예외
- `com.matjom.matjom.common.exception.message.ErrorCode`
  - HTTP 상태와 기본 메시지를 묶어둔 공통 에러 코드 enum
- `com.matjom.matjom.common.exception.handler.GlobalExceptionHandler`
  - `DomainException`, `MethodArgumentNotValidException`, 그 외 모든 예외를 일괄 처리

## 사용 패턴

### 1. 성공 응답

```java
@RestController
@RequestMapping("/members")
public class MemberController {

    private final MemberService memberService;

    @GetMapping("/{id}")
    public MemberResponse getMember(@PathVariable Long id) {
        return memberService.getMember(id);
        // 반환 DTO가 자동으로 ApiResponse.ok(...)에 감싸져 내려갑니다.
    }

    @PostMapping
    public ResponseEntity<ApiResponse<MemberResponse>> createMember(@RequestBody CreateMemberRequest request) {
        MemberResponse response = memberService.createMember(request);
        return ResponseEntity.status(HttpStatus.CREATED)
                .body(ApiResponse.ok(response));
        // 상태 코드 제어가 필요한 경우 ResponseEntity와 ApiResponse를 명시적으로 사용합니다.
    }
}
```

### 2. 실패 응답

```java
@Service
public class MemberService {

    public MemberResponse getMember(Long id) {
        return memberRepository.findById(id)
                .map(MemberResponse::from)
                .orElseThrow(() -> new UserException(ErrorCode.USER_NOT_FOUND));
    }
}
```

- 위 예외는 `GlobalExceptionHandler`가 잡고 다음과 같이 내려보냅니다.

```json
{
  "success": false,
  "error": {
    "code": "USER_NOT_FOUND",
    "message": "회원을 찾을 수 없습니다."
  },
  "timestamp": "2025-09-19T04:00:00Z"
}
```

### 3. 유효성 검증 실패

- `@Valid`가 붙은 요청 DTO가 검증에 실패하면 `MethodArgumentNotValidException`이 발생하며, 첫 번째 오류 메시지를 사용해 `code=INVALID_REQUEST_PARAM`으로 응답합니다.

### 4. 커스텀 실패 응답 직접 반환

```java
@GetMapping("/health-check")
public ResponseEntity<ApiResponse<Void>> healthCheck() {
    boolean healthy = healthService.check();
    if (!healthy) {
        return ResponseEntity.status(HttpStatus.SERVICE_UNAVAILABLE)
                .body(ApiResponse.error(ErrorCode.INTERNAL_SERVER_ERROR, "현재 점검 중입니다."));
    }
    return ResponseEntity.ok(ApiResponse.ok());
}
```

- `ResponseEntity`를 사용하면 advice가 응답을 더 이상 변경하지 않습니다.

## 테스트 팁

- 통합 테스트에서 응답 JSON 구조를 검증하려면 `jsonPath("$.success").value(true)`와 같이 공통 키를 검증하면 됩니다.
- 실패 케이스는 `andExpect(status().isBadRequest())` + `jsonPath("$.error.code").value("INVALID_REQUEST_PARAM")` 조합으로 확인하세요.

## 확장 아이디어

- 프로젝트가 진행되면 서비스별로 `ErrorCode`를 확장하거나 세분화하여 예외 코드 일관성을 유지할 수 있습니다.
- 현재는 `AnyRequest().permitAll()` 상태이므로 인증/인가를 추가하면 오류 응답 포맷도 이 구조를 따르도록 `AccessDeniedHandler` 나 `AuthenticationEntryPoint`를 구현해야 합니다.
