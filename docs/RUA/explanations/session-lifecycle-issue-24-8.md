# 서브 이슈 #24-8: test(session) 경계 조건 단위/통합 테스트 추가

## 배경/문제 정의
- 세션 라이프사이클 로직이 복잡해져 회귀 테스트 없이 배포가 어렵다.
- 현재 테스트는 룰렛/검색에 집중되어 있으며 세션 관련 커버리지가 부재하다.

## 사용자 스토리
As QA 엔지니어,
I want 세션 라이프사이클의 모든 경계 조건이 자동 테스트로 보장되길 원한다
so that 배포 시 안전하게 검증할 수 있다.

## 범위 (In/Out)
**In**
- GeoFenceEvaluator 단위 테스트(반경, dwell, 유예, 정확도)
- 세션 서비스 통합 테스트: 시작 → 위치 → 도착/만료 시나리오
- 멱등/레이트리밋/이벤트 로깅 연동 테스트

**Out**
- 프런트엔드 E2E 테스트
- 비기능(부하) 테스트

## 수용 기준 (AC)
- [ ] Given 사용자가 29m/2.9분 머무르면 도착하지 않는 테스트가 존재한다.
- [ ] Given 사용자가 30m/3.0분 머무르면 ARRIVED 상태가 된다.
- [ ] Given 이탈 9초/11초 시나리오가 각각 dwell 유지/초기화를 검증한다.
- [ ] Given 세션 시작 후 30분 경과 시 EXPIRED로 전환되는 통합 테스트가 존재한다.
- [ ] Given 멱등키 재시도 시 동일 응답을 검증하는 테스트가 존재한다.

## API/계약 영향
- 테스트에서 사용하는 고정 응답을 OpenAPI 예시와 동기화
- 필요 시 Testcontainers(PostGIS, Redis) 설정 보완

## 비기능 요구사항 (NFR)
- `./gradlew test` 기준 전체 테스트 실행 시간이 5분을 넘지 않도록 유지
- 테스트는 멀티 스레딩/타임아웃 이슈에 견고해야 한다.

## 의존성/리스크
- 타임아웃 테스트는 가짜 시계(MockClock) 혹은 가속 기법 필요
- Redis/PostGIS 컨테이너 초기화 시간이 증가할 수 있음 → 재사용 전략 고려
