# 서브 이슈 #24-7: feat(session) 상태 전이 이벤트 로깅 및 권한 트리거

## 배경/문제 정의
- 세션 상태가 어떻게 바뀌었는지 추적할 수 있는 로그가 없어 운영 리포트 작성이 불가능하다.
- 도착/만료/취소 시 후속 권한(예: 추천 재시도 허용) 부여 로직이 미정이다.

## 사용자 스토리
As 운영 분석가,
I want 세션 상태 전이 이벤트가 표준화된 방식으로 적재되길 원한다
so that 리포트를 작성하고 사용자 권한을 자동으로 조정할 수 있다.

## 범위 (In/Out)
**In**
- 상태 전이 이벤트 엔터티/레포지토리 혹은 로깅 규약 설계
- ARRIVED/EXPIRED/CANCELLED/ARRIVED_MANUAL 등 이벤트 기록
- 이벤트 발생 시 재추천 권한/레이트리밋 초기화 등 후속 트리거 연결

**Out**
- BI 파이프라인 연동(향후 5.x 이후)
- 알림/메시징 시스템(별도 프로젝트)

## 수용 기준 (AC)
- [ ] Given 세션 상태가 변경되면, Then 이벤트 로그에 `sessionId`, `userId`, `fromState`, `toState`, `event`, `occurredAt`, `meta`가 저장된다.
- [ ] Given 세션이 ARRIVED 되면, Then 사용자의 추천 재시도 권한/레이트리밋이 초기화된다.
- [ ] Given 이벤트 로그 적재에 실패하면, Then 세션 상태 변경이 롤백되거나 재시도 로직이 동작한다.

## API/계약 영향
- `/api/v1/sessions/*` 응답에 최신 상태와 이벤트 ID를 포함하는 방안 검토
- 이벤트 로그 조회 API는 범위 밖(관측성 9.x에서 다룸)

## 비기능 요구사항 (NFR)
- 이벤트 로그는 idempotent 하게 저장(동일 이벤트 중복 방지 키 필요)
- 로그 저장 실패 시 즉시 경고 알람 발송

## 의존성/리스크
