# 프론트엔드 룰렛 무작위 선택 가이드

백엔드(3.1) 단계에서 `/api/v1/recommendations/roulette`는 **후보 리스트**만 내려주고, 실제 무작위 선택·멱등 처리는 프론트엔드가 담당합니다. 이 문서는 프론트 작업 범위와 인터페이스를 정리한 참고용 문서입니다.

---

## 1. 목표

1. 백엔드에서 받은 추천 후보 리스트를 기반으로 클라이언트에서 균등 난수로 1개 후보를 선택한다.
2. 동일한 `Idempotency-Key`와 요청 파라미터 조합에 대해 60초 이내 재요청 시 동일한 결과를 보여주도록 프론트가 캐싱/재생한다.
3. 선택 결과를 UI에 반영하고, 필요 시 사용자 행동(“다시 돌리기”)에 맞춰 새로운 멱등키로 재호출한다.

---

## 2. 백엔드 응답 계약

`POST /api/v1/recommendations/roulette`

```json
{
  "success": true,
  "data": {
    "candidates": [
      { "placeId": 101, "name": "매콤식당", "distanceMeters": 45.6 },
      { "placeId": 123, "name": "순대국명가", "distanceMeters": 98.1 }
    ],
    "metadata": {
      "generatedAt": "2025-02-27T05:00:00Z",
      "seedSuggestion": null
    }
  },
  "timestamp": "2025-02-27T05:00:00Z"
}
```

> 실제 응답 구조는 추후 3.2 단계 백엔드 구현 시 확정 예정이지만, 프론트는 `data.candidates[]` 배열이 내려온다는 가정 하에 작업을 진행한다.

---

## 3. 프론트 구현 단계

1. **멱등키 생성 및 요청 전송**
   - 매 요청마다 UUID 등 고유 값을 `Idempotency-Key` 헤더로 생성.
   - 요청 파라미터(lat, lng, radius 등)는 백엔드와 동일하게 사용.

2. **후보 리스트 수신**
   - `data.candidates`가 비어 있으면 “후보 없음” UI 처리.
   - 후보가 1개 이상이면 랜덤 선택 로직으로 넘어간다.

3. **균등 난수 선택**
   - `Math.random()` 또는 표준 난수 생성기를 사용해 0~(N-1) 범위에서 인덱스를 선택.
   - 추후 시드 기반 재현이 필요하면, 로컬에 시드값을 저장하거나 사용자 설정으로 노출.

4. **멱등 재생 처리**
   - 동일 `Idempotency-Key`로 재시도 시 백엔드에도 동일 후보 리스트가 내려오는 것을 가정.
   - 프론트는 (1) 기존에 캐싱한 난수 인덱스를 재사용하거나, (2) 백엔드가 후보 리스트를 동일 순서로 내려주므로 재랜덤 대신 캐시된 인덱스를 재사용.
   - 멱등 기간(60초) 이후라면 새로운 키로 재시도.

5. **UI 반영**
   - 선택된 후보를 팝업/룰렛 애니메이션/카드 등에 표시.
   - “다시 추천” 버튼을 누르면 새 멱등키로 1~4 과정을 반복.

6. **로그/분석 이벤트**
   - 사용자에게 노출된 최종 후보 ID를 로그/분석 이벤트로 기록하여 추후 통계에 활용.

---

## 4. 에러 처리 가이드

- **400(`Idempotency-Key` 누락)**: 프론트 요청 코드에서 헤더가 누락되었는지 확인하고 디버그 메시지 노출.
- **429(레이트리밋)**: 백엔드에서 내려주는 `Retry-After`를 사용해 UI에 재시도 가능 시점을 안내.
- **기타 에러**: 공통 에러 핸들러에 따라 토스트/알림으로 처리.

---

## 5. QA 체크리스트

- [ ] 동일 파라미터 + 멱등키 요청을 2회 연속 보내면 같은 후보가 UI에 노출되는지 확인.
- [ ] 멱등키를 변경하면 다른 랜덤 결과가 나올 수 있는지 확인.
- [ ] 후보 리스트가 비어 있을 때 적절한 빈 상태 UI를 제공.
- [ ] 레이트리밋 응답(`429`) 수신 시, `Retry-After` 초만큼 대기한 뒤 재시도.

---

## 6. 참고

- 백엔드 3.2~3.5 항목은 프론트 전담으로 이관되었습니다. 관련 작업 내용은 본 문서를 최신 상태로 유지하며 관리합니다.
