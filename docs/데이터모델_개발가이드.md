# 데이터 모델 개발 가이드 (주니어용)

이 문서는 MATJOM Geo/Place 서비스에서 사용하는 핵심 데이터 모델과 코드 매핑 방법을 쉽게 이해할 수 있도록 정리한 가이드입니다. 모든 테이블은 `BaseEntity`(공통 `created_at`, `updated_at`, `deleted_at`)를 사용하며, 소프트 딜리트를 염두에 둔 설계입니다.

## 전체 구조 요약

```
User (uuid PK)
  └─< Visit (visit_id)
          └─< VisitPosition (pos_id)
  └─< UserPlaceFirstArrival (user_id + place_id)

Place (place_id)
  └─< Visit (FK)
  └─< UserPlaceFirstArrival (FK)
```

- **schema-postgres.sql** ( `src/main/resources/schema-postgres.sql` )에서 모든 테이블/인덱스/제약을 한 번에 정의합니다. PostgreSQL 프로필(dev/prod/test)이 실행될 때 자동 적용됩니다.
- PostGIS/uuid 확장은 인프라 단계에서 한 번 설치해 두어야 합니다 (`CREATE EXTENSION postgis;`, `CREATE EXTENSION "uuid-ossp";`).
- PostgreSQL + PostGIS + uuid 확장을 사용하므로 최초 한 번 `CREATE EXTENSION` 구문을 실행합니다.

## 엔티티별 필드 요약

### 1. User (`src/main/java/.../user/entity/User.java`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | `UUID` | PK. `@UuidGenerator`로 자동 발급 |
| email, name | `String` | 로그인 및 닉네임 |
| password | `String` | LOCAL 계정만 사용 |
| provider | `AuthProvider` enum | 로그인 경로 (LOCAL/GOOGLE/KAKAO/NAVER) |

**DB 제약**
- `uq_user_email_provider`: 동일 provider 안에서 이메일 중복 금지
- `chk_password_required`: `LOCAL` → password 필수, 그 외 → password는 NULL

### 2. Place (`src/main/java/.../place/entity/Place.java`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | `Long` | BIGSERIAL PK |
| latitude/longitude | `BigDecimal(9,6)` | 지도 좌표. `updateLocation()`에서 `Point` 생성 |
| category | `String[]` (getter는 `List`) | `text[]` 배열 (`@JdbcTypeCode(SqlTypes.ARRAY)`) |
| providerId, phoneNumber | `String` | 외부 원천 식별자 / 연락처 |
| workingHours, breakTime, openedAtSource | `JsonNode` | JSONB 필드 (`@JdbcTypeCode(SqlTypes.JSON)`) |
| openedAt | `LocalDate` | 인허가일 |
| bizStatus + 주소 5종 | `String` | 행정구역 필터용 |
| location | `Point` | PostGIS geometry(Point,4326). lat/lng에서 자동 생성 |

**DB 인덱스**
- `idx_places_location`: GIST 공간 인덱스 (반경 검색)
- `idx_places_lower_name`: `lower(name)` 함수 인덱스 (대소문자 무시 검색)
- `idx_places_category`: GIN 배열 인덱스 (카테고리 필터)

### 3. Visit (`src/main/java/.../visit/entity/Visit.java`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | `Long` | BIGSERIAL PK |
| user / place | `ManyToOne` | FK (user_id uuid, place_id bigint) |
| state | `VisitState` enum | ACTIVE/ARRIVED/EXPIRED/CANCELLED |
| clientMode | `ClientMode` enum | NAVIGATION/IDLE |
| startedAt, arrivedAt, cancelledAt, expiredAt | `OffsetDateTime` | 상태 전이 타임스탬프 |
| lastPositionAt | `OffsetDateTime` | 마지막 위치 수신 시간 |
| dwellStartedAt | `OffsetDateTime` | 180초 체류 타이머 시작 시각 |
| lastLatitude/Longitude | `BigDecimal(9,6)` | 마지막 좌표 |
| lastAccuracyMeter | `BigDecimal(6,2)` | 마지막 정확도 |
| meta | `JsonNode` | 디버그/확장용 JSONB |

**DB 인덱스/제약**
- `chk_visit_state`, `chk_visit_client_mode`: 허용 enum 값 강제
- `uq_visits_active_user`: `state='ACTIVE'`인 방문은 사용자당 1개만 허용 (부분 인덱스)
- `idx_visits_started_at`: 타임아웃 배치용 검색 최적화

### 4. VisitPosition (`src/main/java/.../visit/entity/VisitPosition.java`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | `Long` | BIGSERIAL |
| visit | `ManyToOne` | 방문 세션 FK |
| latitude/longitude | `BigDecimal(9,6)` | 위치 이벤트 좌표 |
| accuracyMeter | `BigDecimal(6,2)` | 정확도 |
| mode | `ClientMode` enum | 이벤트 수신 모드 |
| receivedAt | `OffsetDateTime` | 이벤트 수신 시각 |

**DB 인덱스**
- `(visit_id, received_at)` 복합 인덱스: 리플레이/순서 보장

### 5. UserPlaceFirstArrival (`src/main/java/.../visit/entity/UserPlaceFirstArrival.java`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| id | `@EmbeddedId` (userId UUID + placeId Long) | 복합 PK |
| firstArrivedAt | `OffsetDateTime` | 첫 방문 시각 |

> 엔티티 생성자에서 `new UserPlaceFirstArrivalId(user.getId(), place.getId())`로 PK를 설정합니다.

## JSON / 배열 매핑 사용법

의존성 추가 없이 Hibernate 6 표준 타입으로 매핑할 수 있습니다.

```java
@JdbcTypeCode(SqlTypes.JSON)
@Column(columnDefinition = "jsonb")
private JsonNode workingHours;

@JdbcTypeCode(SqlTypes.ARRAY)
@Column(columnDefinition = "text[]")
private String[] category;
```

- Jackson의 `JsonNode`를 그대로 사용하면 DTO ↔ Entity 변환이 편합니다.
- 커스텀 값 객체가 필요하면 별도의 클래스를 만들고 Jackson(ObjectMapper)으로 직렬화하면 됩니다.

## DDL (schema-postgres.sql) 확인 포인트

1. **확장**: `uuid-ossp`, `postgis` 확장을 먼저 생성합니다.
2. **제약/인덱스**
   - 사용자 이메일+provider 유니크 + password CHECK
   - 장소 GIST/GiN/함수 인덱스
   - 방문 세션 상태/모드 CHECK, partial index로 ACTIVE 세션 제한
   - 방문 위치 복합 인덱스
3. **소프트 딜리트 필드** (`deleted_at`)는 실제 삭제 대신 업데이트로 관리됩니다.

## UC 요구사항과 매핑

| UC | 핵심 컬럼/테이블 | 비고 |
| --- | --- | --- |
| UC-GEO-1/4 (지오펜스, 근처 통과) | `Visit.dwellStartedAt`, `VisitPosition`, `Place.location` | 30m/180s 판정 시 필요한 데이터. 위치 정확도는 `lastAccuracyMeter` 사용 |
| UC-GEO-2 (오도착 정정) | `Visit.state`, `arrived_at`, `cancelled_at` | 수동 확정 API에서 상태 전이 제어 |
| UC-GEO-3 (목적지 변경) | `Visit.cancelled_at`, partial index | 중복 ACTIVE 방지 |
| UC-GEO-5 (세션 종료) | `started_at`, `expired_at`, `state` | 배치가 인덱스로 빠르게 조회 |
| UC-GEO-6 (검색/룰렛) | `Place.category`, `Place.location`, `UserPlaceFirstArrival`, `opened_at` | 미방문 여부, 신규 판정, 반경/정렬에 사용 |
| UC-GEO-7 (완화) | `Place` + 검색 응답 메타 | 완화 전략은 응답 메타로 전달, 필요 시 로그 테이블 추가 |

## 개발 시 체크리스트

- [ ] 새로운 엔티티를 추가하면 `schema-postgres.sql`에 동일한 DDL/인덱스를 반영한다.
- [ ] ENUM은 문자열로 저장(`EnumType.STRING`)하여 순서 변경 이슈를 피한다.
- [ ] 위치 계산이 필요한 서비스 로직에서 `Place.getLocation()` (Point)을 사용하면 PostGIS 함수(`ST_DWithin`, `ST_Distance`)를 그대로 호출할 수 있다.
- [ ] 소프트 삭제가 필요한 경우 `entity.markDeleted()`를 호출하고 쿼리 시 `deleted_at IS NULL` 조건을 포함한다.
- [ ] 테스트 환경에서도 PostGIS 확장이 필요하므로 Docker 컨테이너(PostGIS 이미지)를 사용한다.
- [ ] 통합 테스트는 Testcontainers(PostGIS 16-3.4)를 사용하도록 `application-test.yml`이 구성되어 있으므로 Docker가 실행 중인지 확인한다 (`TC_INITSCRIPT=tc-init.sql`에서 확장을 생성).

## 자주 묻는 질문

**Q. JSON 필드를 DTO로 어떻게 변환하나요?**  
A. 서비스/컨트롤러 레이어에서 `ObjectMapper`를 주입 받아 `JsonNode` ↔ DTO를 변환하면 됩니다. 반복되는 변환이 있다면 Converter 유틸 클래스를 만들어 공유하세요.

**Q. 카테고리 배열에 인덱스를 어떻게 걸죠?**  
A. `schema-postgres.sql`에 이미 `CREATE INDEX ... USING GIN (category)`가 포함돼 있습니다. 다중 카테고리 `WHERE '일식' = ANY(category)` 같은 쿼리가 빠르게 동작합니다.

**Q. 방문 세션은 왜 `dwell_started_at` 컬럼이 있나요?**  
A. 180초 연속 체류 판정(UC-GEO-1/4)을 서버가 재시작해도 이어가기 위함입니다. 클라이언트 이벤트로만 판단하면 타임라인이 끊길 수 있습니다.

**Q. 부분 인덱스는 어떻게 관리하나요?**  
A. Spring JPA는 부분 인덱스를 생성하지 못하므로 `schema-postgres.sql`에 직접 정의했습니다(`state='ACTIVE'`). 데이터베이스를 초기화하면 자동으로 적용됩니다.
